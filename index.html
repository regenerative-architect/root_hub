Section I

Project Root Hub Overview

Purpose

The Root Hub centralizes navigation, state monitoring, and insight dashboards for all project modules. It integrates offline persistence, gamified HUD displays, and access to individual modules for interactive exploration — all within this single page.

Scope

Every module below is presented as an embedded panel rather than an outbound link, so the whole dashboard functions as one self-contained page for educational modeling and scenario review.

Who This Is For

This dashboard is built for the people who have to act on this material — policymakers and corporate decision-makers weighing real interventions — while staying usable for the educators and students exploring the same questions alongside them.

How This Hub Works

Every case file lives inside this same page as an expandable panel rather than a separate link, so the whole dashboard works as one self-contained file, online or off.

Project Structure

This hub is organized into ten sections, each reachable from the folder tabs above: Overview, Modules, Methodology, Principles, Clearance, Evidence, Architecture, Roadmap, Changelog, and Reference. The first four orient you; Clearance and Evidence are the interactive layers; the last four are technical and historical documentation.

Design Philosophy

The paper-and-ink motif — a stamped splash, folder-tab navigation, a pinned Evidence Board — is a deliberate choice. Dossier framing keeps the subject matter grounded in documentation and reference rather than spectacle, which matters more for a tool meant to support real policy reading than a flashier interface would.

Finding Your Way Around

The search bar indexes every section of this hub, and jumps straight to a result when clicked. Press Ctrl/Cmd+K (or the Quick Jump button) for the same index as a command palette. The badge beside the theme toggle tracks your own exploration progress, and the Evidence Board gives you a visual map of which case files you've opened.

Section III

Methodology

How the case files are meant to be read and weighed, once their content is integrated.

A Shared Analytical Frame

Each of the twelve case files approaches a different facet of the same underlying problem — how corruption, coercion, and conflict interact, and what interrupts that cycle. They're designed to be read as complementary lenses rather than standalone verdicts: a diplomacy-window reading means more alongside a supply-chain or accountability-pressure reading of the same situation.

Reading a Case File

When any case file's content is integrated, the same questions apply regardless of subject: what assumptions is this analysis making, what time horizon does it cover, what isn't being modeled, and how would the conclusion change if a key input were different? Treating a module's output as one input among several — not a final answer — is the intended use.

Evaluating Findings

Policy-relevant analysis is only as good as its transparency about uncertainty. Any output from this suite that doesn't show its assumptions, or that reads as more precise than a complex real-world system reasonably allows, should be treated with proportionate skepticism.

Limits of Simulation

No model of corruption, conflict, or economic pressure captures every variable — human behavior least of all. This hub treats every module as a structured way to think, not a prediction engine, and none of its outputs are meant to substitute for domain expertise, current intelligence, or professional judgment on real situations.

Section IV

Principles

The commitments below govern how every part of this hub — including all twelve case files — is designed and framed.

Zero-Harm Commitment

This hub is built on the premise that a tool for understanding corruption, conflict, and recovery should never itself become a vector for harm. Nothing here is designed to identify targets, coordinate action against real individuals or groups, or provide operational instructions of any kind — only frameworks for understanding.

Anti-Inversion, In Practice

Several of the subjects this hub organizes — dominance dynamics, economic pressure, escalation risk — can be read two ways: as something to understand and counter, or as a set of instructions. This hub is built for the first reading only. Where a subject could plausibly be misread as the second, its framing here stays at the level of general, publicly documented fields of study rather than specific tactics or figures.

Non-Partisanship

This hub's frameworks are built to apply regardless of which actors or parties are involved in a given real-world situation. No case file is designed around, or names, specific real people, governments, or organizations.

No Fabricated Findings

Where a case file's real content isn't yet integrated, this hub says so plainly — "Content Pending" — rather than filling the space with invented data dressed up as real analysis.

Educational Use, Not Operational Guidance

Everything in this hub — including all twelve linked modules — is intended for policy literacy, classroom use, and civic research. It is not a substitute for professional analysis, legal counsel, or official guidance, and nothing here should be treated as instructions for real-world action.

Accessibility

Every tab, case file, and control here is keyboard- and screen-reader-navigable, with ARIA roles and roving tabindex on the tab system (arrow keys move between tabs) and full support for prefers-reduced-motion.

Local-First Privacy

The only data this hub collects is your own exploration progress and any notes you choose to write, and none of it leaves your browser. It's stored in IndexedDB, is entirely optional (see the tracking toggle in Clearance), and clears completely with the Reset button — or you can export it yourself first, from Architecture.

Section V

Field Clearance — Progress & Commendations

HUD Overview

The Root Hub HUD displays aggregated metrics from this hub's own use — activity, offline state, and progress tracking. HUD state persists offline using IndexedDB.

Reset & Persistence

Users can reset the global HUD and all offline states. This ensures safe experimentation without permanent data loss. Consider exporting your data first (Architecture tab) if you want to keep a copy.

How Scoring Works

Every tab visited (once) is worth 5 Intel. Every case file opened (once) is worth 10. Switching themes and using search (or the command palette) are each a one-time 5-point bonus. With ten tabs and twelve case files, full clearance tops out at 180 Intel — the Director rank at Level 5. None of this is scored against anyone else; it's a private, local record of your own review. Writing notes isn't scored — it's a tool, not a milestone.

Progress & Commendations

Progress reflects how much of this dossier you've reviewed — visiting tabs, opening case files, switching ink modes, and searching the index. Stored only in this browser via IndexedDB; nothing is sent anywhere.

Section VII

Architecture

A technical reference for how this file actually works, for whoever maintains or extends it next.

State Model

Everything the hub remembers lives in one JavaScript object: which theme and tab are active, which tabs and case files you've visited, whether you've toggled themes or used search, whether progress tracking and reading mode are on, your per-module notes, and which commendations you've unlocked. That single object is what gets saved to and loaded from storage — no scattered state to keep in sync.

Search Index Design

Rather than scanning the live page — which would miss whatever tab isn't currently visible — search and the command palette both run against the same hand-maintained index: an array of tab/anchor/text entries, one per reference block and case file. A match jumps to the right tab, opens the right panel, and scrolls it into view.

Rendering Pipeline

Tab switching never reloads or re-fetches anything — it toggles a CSS class that shows one panel and hides the rest, and moves keyboard focus and tabindex along with it. Scroll-triggered fades use an IntersectionObserver rather than a scroll-position calculation, and every color in the interface comes from CSS custom properties, so the Frost/Fire toggle needs to change only a handful of variable values to reskin the entire page.

Storage Schema

All persisted data sits in a single IndexedDB object store named prefs, under one key: state. That's a deliberate simplification — one record, one shape, no migrations to manage as the hub grows, at the cost of not being queryable by sub-field, which this hub has never needed.

Your Local Data

Everything this hub knows about your session — theme, progress, notes — lives in the object below, pulled live from IndexedDB and updated every time anything changes. Export it to back it up or move it to another browser; import a previous export to restore it. Imported files are checked before use — anything malformed is rejected rather than silently breaking the hub.

Section VIII

Roadmap

An honest account of what's actually built versus what's still open — including a couple of gaps against the original brief.

What's Built
  • Offline-first persistence — theme, tab, notes, and Field Clearance progress via IndexedDB
  • The tab-based single-page architecture, with no outbound links anywhere
  • Cross-tab search with jump-to-block, plus a Ctrl/Cmd+K command palette over the same index
  • Keyboard-navigable tabs (roving tabindex, arrow keys) and full screen-reader support
  • Per-case-file private notes, auto-saved locally
  • Export/import of your local data as a JSON file, with basic validation on import
  • A live State Inspector so the "local-first" claim is checkable, not just asserted
  • A Reading Mode toggle that dims chrome for focused review
  • The Evidence Board and Clearance gamification systems
  • prefers-reduced-motion handling, a print stylesheet, and a no-JavaScript fallback
What's Pending
  • The twelve case files' own interactive content — currently placeholder slots by design
  • A formal code license — a placeholder line sits in Attributions & Licensing, awaiting your choice
  • Multi-language support — the original brief called for storing a language preference in IndexedDB, and the storage layer could hold one, but no translation or language switcher has been built yet
Open Questions
  • Whether each case file's real content will be pasted directly into this file or embedded some other way
  • Which license this codebase should carry
  • Whether additional ink modes beyond Frost and Fire are wanted
  • Whether the module Field Notes and per-file notes fields added over the last few passes are the right scope, or should be trimmed back
  • What functionality, specifically, is still missing — this hub can keep growing, but it grows better toward a named target than toward "more" in the abstract

Tools & Technologies

Implemented in this file

  • IndexedDB — persists theme, tab, notes, and Field Clearance progress across sessions, no server round-trip.
  • CSS custom-property theming — powers the Frost/Fire ink-mode switch throughout.
  • SVG feTurbulence — generates the procedural paper-grain texture with no image file.
  • Debounced, sanitized client-side search and command palette — index every tab, not just the visible one.
  • Roving-tabindex keyboard navigation on the tab list, per the WAI-ARIA tabs pattern.
  • File-based export/import via the Blob and FileReader APIs, with input validation on the way back in.
  • prefers-reduced-motion handling — skips choreography for visitors who've asked for it.
  • Print stylesheet — strips decorative layers for a clean printed page.

Referenced patterns, not loaded here

  • Dexie.js-style transaction safety, Workbox service-worker caching, D3.js / Cytoscape.js graph visualization, Three.js 3D rendering, LocalForage — named as relevant prior art for where linked modules could go, not as dependencies of this file. This file loads zero external libraries.

Frequently Asked Questions

Why do the case files say "Content Pending"?

By design — this hub is built as one self-contained page with embedded slots for each module, rather than linking out. The slots are ready; the modules' own content integrates later.

Does this hub send my data anywhere?

No. Everything tracked — theme, tab, notes, exploration progress — stays in your browser's IndexedDB. There are no network calls in this file. The State Inspector in Architecture shows exactly what's stored, live.

Does it work without an internet connection?

Yes, after the first load. There are no external dependencies, fonts, or scripts to fetch.

How do I reset my progress?

Use "Reset RootHub State" under Reset & Persistence in the Clearance tab. Export your data first (Architecture tab) if you want a backup.

Can I print this page?

Yes — the print stylesheet strips decorative layers and expands every tab into a single printable document.

What does "Zero-Harm & Anti-Inversion" mean?

See the Principles tab for the full explanation — the short version lives in the footer of every page.

Why isn't there a language switcher, even though the code stores a language preference?

The storage layer was built to hold one, but translation and a language switcher haven't been built yet — see Roadmap for the full list of what's pending.

Can I reuse this file's code for my own project?

See Attributions & Licensing below — no restricted code is used, though the license line itself is still a placeholder pending your choice.

What happens if I clear my browser's site data?

Root Hub returns to its defaults, including your notes. Export your data first from the Architecture tab if you want to keep it.

Are my per-case-file notes shared with anyone?

No — they're stored the same way as everything else: locally, privately, and only visible to you in this browser.
